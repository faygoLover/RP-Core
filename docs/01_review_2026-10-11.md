## 1. Фото игрока → служба в RP Core
Сейчас фото для медкарты принимает Medicine (`medcard/MedcardStore.onPhoto`), и там дыра:
- снимок принимается в любой момент, пока фото нет, даже если сервер его не просил (`PHOTO_ASKED` не проверяется);
- картинка целиком распаковывается через `ImageIO.read` и только потом проверяется размер. PNG на 30 КБ может
  объявить размер 25000×25000, и сервер займёт под него сотни мегабайт. Пачкой таких — лаги или падение.

Решение: общая служба фото в Core, ею пользуются медкарта Medicine и будущий RP PDA.
- Клиент рисует портрет по скину по запросу сервера.
- Сервер принимает снимок только после своего запроса, не чаще раза в N секунд, до 30 КБ.
- Ширина и высота читаются из заголовка (`ImageReader.getWidth(0)` / `getHeight(0)`) **до** распаковки: 64–512 × 32–512.
- Хранение: файл на игрока в папке мира. Раздача клиентам с кэшем.
- В Core для этого нужен свой сетевой канал (сейчас его нет), он пригодится и дальше.

## 3. Связь через Core — модульно
Правило:
- **Через Core** — то, чем пользуются несколько модов семейства и что должно работать без соседа.
- **Напрямую** — разовая связь с одним конкретным модом (TaCZ, LSO).

**Модульно** значит: Core — набор независимых «розеток» (навыки и черты, тело, питание, выносливость, фото, HUD).
Каждая — интерфейс плюс пара методов в `RpCoreAPI`. Мод подключает только те, что ему нужны. Розетка без хозяина
просто отвечает «никто не ведёт», как сейчас `nutrition()` возвращает null.

**Зачем тогда RP Stamina.** В Core переезжает только розетка, вся механика остаётся в Stamina: траты, восстановление,
броня, предметы, HUD, настройки. Розетка — это несколько вопросов («сколько выносливости», «потратить N», «измотан
ли») и событие нагрузки (уже есть `ExertionEvent`). Без Stamina розетка пустая, и моды обходятся без выносливости.

Кандидат на первую новую розетку — выносливость (`StaminaProvider`). Сейчас в Stamina лезут двое: Medicine вызывает
`StaminaAPI` напрямую (`integration/StaminaCompat`), Culinary ищет атрибут `rpstamina:max_stamina` по имени. Третьим
будет мод тренировок.

## 6. Аудит команд
Все команды семейства начинаются с `/rp…`.

| Сейчас | Решение |
|---|---|
| `/rpcore`, `/rpcore skill <игрок> <навык> [уровень\|reset]` | оставить. Подсказки по Tab — свои переводы Core (`skill.rpcore.*`), а не `skill.rpperks.*`. Без перевода подсказка — просто имя навыка |
| `/rphud` | оставить — единый редактор HUD |
| `/perks` | → `/rpperks` |
| `/perksadmin [игрок]` | → `/rpperks admin [игрок]` |
| `/stamina get\|set\|add\|refill\|reload\|export_defaults\|debug` | → `/rpstamina …` |
| `/staminahud` | убрать (то же, что `/rphud`) |
| `/rpmedicine hud` | убрать (то же, что `/rphud`) |
| `/rpmedicine skill` | убрать (дублирует `/rpcore skill … medicine`) |
| `/rpmedicine kit` | убрать (п. 5) |
| `/rpmedicine food add` | при Culinary передавать ей (`/rpculinary advance`), не дублировать |
| `/rpmedicine set … protein/fat/carbs/vitamins/weight` | при Culinary это её данные — не дублировать |
| отладочные: `/rpmedicine profile`, `/rpstamina debug`, `/rpstamina export_defaults`, `/rpculinary audit` | за настройкой «отладочные команды» в конфиге |
| `/fl_zone_arts` | не RP-семейство, не трогаем |

**Баг:** в `/rpmedicine set` два параметра называются `fat`: жир тела (2–60) и нутриент «жиры» (0–120). Brigadier
сливает одноимённые ветки, второй обработчик перекрывает первый. Итог: команда берёт границы жира тела, а меняет
нутриент; жир тела командой не поставить. Решение: жир тела везде называется `bodyfat`, как в Culinary.

Потом (уже в плане, п. 3–4 `00_plan.md`): общий список команд в `/rpcore` и одна перемотка времени `/rptime` вместо
`/rpmedicine time add`, `/rpmedicine food add` и `/rpculinary advance`.

## 9. Подмена ванильной сытости — сделать элегантно
Требования брата: не нагружать сервер, не путать моды, сделать красиво.

Сейчас сытость подменяют два мода:
- **Stamina (клиент)** каждый тик подменяет уровень сытости на 0 или 20, чтобы разрешать или запрещать бег
  (`client/ClientEvents.onPlayerTick`), а после тика возвращает. Другие моды в этот момент видят фальшивые цифры.
- **Culinary (сервер)** держит ванильную сытость на 7 («есть место в желудке»: есть можно, бегать можно, ванильное
  лечение от еды выключено) или на 20 («полон»: обычная еда не лезет). Насыщение и усталость всегда 0.

Решение:
- **Stamina**: одна маленькая клиентская вставка (миксин) в ванильную проверку
  `LocalPlayer.hasEnoughFoodToStartSprinting()`: решает Stamina (измотан — нельзя; голод не мешает, если так в конфиге).
  Подмена в тике убирается. Нагрузки на сервер ноль, и ни один другой мод больше не видит фальшивую сытость.
- **Culinary**: замок 7/20 — сознательное решение, без миксинов в проверку «можно ли есть» его не обойти. Оставляем,
  но записываем в Core правило: **ванильной сытостью владеет мод питания**, остальные моды семейства её не трогают.

## 10. Навыки
Брат решил:
- **Форма → «Телосложение»** (только название). Id `rpcore:fitness` лучше не менять, чтобы не ломать сохранения.
- **Сила и Телосложение требуют в 10 раз больше опыта** на уровень. Наверстаем тренировками (мод фитнеса).
  Отдельный множитель в конфиге Perks, например `physical_xp_cost = 10`.
- **Потеря Силы и Телосложения настраивается и отключается в конфиге.** Сейчас её можно выключить только
  `physical_decay_per_minute = 0`. Сделать явный переключатель.
- Остальное по навыкам не трогаем.

### Как навыки растут сейчас (для справки)
- 9 навыков, уровни 0–10: Медицина, Кулинария, короткоствол, длинноствол, тяжёлое оружие, взрывчатка, ближний бой,
  Сила, Форма.
- Итоговый уровень:
  - уровень ГМа, если задан;
  - иначе наработанный, но не ниже уровня от перков (из нескольких — наибольший);
  - «Плохая координация» — −1 к огнестрелу; у «Пацифиста» боевые не выше 1.
- Сила и Форма: старт 4. Физические перки задают старт и дальше следуют за уровнем: Слабак 0–2, Силач 7–10,
  Задохлик 0–2, Выносливый 7–8, Атлет 9–10. После 30 минут онлайн без нагрузки — −1 опыта в минуту.
- Цена уровня: 150 × 1,6^уровень. 0→1 — 150, 4→5 — 983, 9→10 — 10 308, всего 0→10 — 27 238.
- Откуда опыт:
  - огнестрел — 0,15 за выстрел и 1 за попадание по живому;
  - ближний бой — 1 за удар по живому;
  - Сила и Форма — 1 за 100 потраченной выносливости (минута бега ≈ 9,6 опыта);
  - Медицина — (2 + мин. уровень действия) × «полезность» (0, если ты на 4+ уровня выше) × 0,6 за каждый повтор на том
    же пациенте за 10 минут, диагностика ×0,5;
  - Кулинария — так же, по сложности блюда.

## 11. Мод фитнеса (дополнение к п. 7 `00_plan.md`)
- **Мышечная усталость** по группам мышц. Группа и нагрузка зависят от упражнения или действия: категории Stamina
  (ходьба, плавание, копание, удары) — основа.
- **Перегрузка**: сначала усталость и падение пользы от тренировки, при чрезмерной нагрузке — боль, потом травмы
  (растяжение, надрыв). Последствия ведёт Medicine, нужен новый вызов в `BodyProvider` («перегрузка части тела»).
- Чем ниже Сила и Телосложение, тем раньше наступает усталость.
- **Связь с Кулинарией**: для роста нужны определённые нутриенты (например, белок), или они быстрее тратятся во время
  упражнений.
- Связь — через Core (розетки выносливости, тела, питания, навыков).
